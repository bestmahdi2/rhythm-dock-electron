Updated 2026-10-02. [TASKS.md](../TASKS.md) contains the checked implementation
backlog. [ROADMAP.md](ROADMAP.md) retains the phase design and current status.
The local [documentation page](index.html) links the guides without a server.

## Open the tools

In **Settings**, select **Open tools**, or use **Ctrl+K** (**Cmd+K** on macOS)
to search actions. The tools dialog grows within the window and scrolls in compact
layouts. The original Player, Playlist and Settings tabs remain the main navigation.

| Area | What works now |
|---|---|
| Library | Paged search/sort, 40-row window, artist/album art, lazy folders, checkbox/visible-range Shift selection, play/queue/tag selection, history, duplicate candidates, named/smart playlists |
| Appearance | Five theme colors/JSON, restricted CSS, art accent, optional waveform and spectrum/scope/VU/spectrogram; full-screen Now Playing from palette |
| Practice | A–B/slowdown, manual tempo, metronome/count-in, named bookmark save/jump/delete and parametric EQ/AutoEQ |
| Audio editor | Reordered cuts, gain/fades, section loop preview, undo and new-file export with optional pitch render |
| Tags & files | Reviewed batch/pattern preview, apply/undo, organization, metadata matching and cover/preset tools |
| Radio & podcasts | Saved direct stations/directory lookup, RSS/Atom subscriptions, bounded downloads, save and resume |
| Accounts | Last.fm authorization, ListenBrainz token, pending listens, similar artists, Discord status and AcoustID configuration |
| Getting started | Folder selection, server health/save, Sharing navigation and explicit saved-host resume |
| Layouts | Up to 20 named geometry/layout/pin/edge presets |
| Settings & logs | Preferences import/export, installed login startup, notifications, local diagnostics and opt-in reporting |

The library uses SQL paging (maximum 200 tracks/request); rendered lists keep 40
track rows. Album/artist browsing loads 40 groups at a time, up to 2,000 groups.
Shift selects the visible loaded range; selection persists across pages. History
keeps 10,000 records and displays the newest 200. Duplicate candidates compare
title, artist and rounded duration and require manual file review.

Smart playlists apply AND rules for artist/album/genre, minimum rating, unplayed
days and maximum duration. Smart playlists, history and bookmarks are included in
library backup/merge restore (backup format 6, additive database schema 13).

## Optional audio tools

Configure FFmpeg in the existing audio-tool settings, or have `ffmpeg` on PATH.
See [AUDIO-TOOLS.md](AUDIO-TOOLS.md). No executable is bundled or downloaded by the app.

Waveforms are generated by streaming low-rate PCM into 512 peak bins and cached
against file size/mtime. Changing songs cancels stale generation. Failures leave
the standard progress bar usable. Visualizers are optional and stop drawing while
hidden; reduced-motion preferences hide their canvas.

The editor exports 1–32 sections to a **new** WAV/FLAC/MP3/M4A/OGG file. Gain and
fades apply per cut; ±12-semitone pitch rendering keeps the summed duration. Preview
loops the selected original section; it does not audition export effects or pitch.
Drafts/50-step undo are session-only. Source files and occupied output names are
preserved. Real FFmpeg fixtures check duration, metadata and original bytes.

Practice tempo is manually selected (30–300 BPM). The click uses the common audio
master and follows playback rate, with four clicks before starting. Pause/end/
unload cancels scheduled clicks. Automatic BPM/key detection and live independent
pitch shifting still need implementation. Hardware listening is required to accept
audible timing and sound quality.

Parametric EQ supports up to 16 bands, Q 0.1–20, gain ±24 dB and preamp −36–0 dB.
AutoEQ text supports enabled `PK`, `LS` and `HS` filters. Applying it bypasses the
graphic filter chain; switching back to graphic EQ disables the parametric setting.
The response curve is indicative; user profiles and headphone quality need listening.

## Safe tag and file changes

Select songs in Library (or use the current song), then open **Tags & files**.
Preview is mandatory. Tag fields with empty inputs are left unchanged. Patterns use
`%artist%`, `%albumArtist%`, `%album%`, `%title%`, `%genre%`, `%year%`, `%track%`,
`%disc%` and `%comment%` where applicable; unsupported fields/path traversal fail.
Use patterns such as `%artist%/%album%/%track% %title%` for organization.

Batches are bounded to **50 files / 512 MB**. Tag changes copy originals into
`RhythmDock/file-operations/`; undo restores all original bytes only if files still
match their post-change hashes. Backups/journals are retained for user-controlled
recovery and can grow on disk. Organization verifies exclusive copies before
removing originals and updates library roots, history, bookmarks, playlists and
the live queue. A safely verified interrupted copy can be undone. Changed files
or occupied original names stop undo and preserve files for review.

Organization moves **audio files only**. Companion LRC/CUE files remain in their
original folders; moving them with an album still needs implementation. Automatic
rating/ReplayGain tag sync and persistent editor projects are also open.

MusicBrainz matching and cover selection only fill preview fields; they do not
silently overwrite tags. Audio identification requires a Chromaprint **fpcalc**
executable and an **AcoustID application key** in Accounts. The actual fpcalc/live
identification acceptance is pending. Artwork is fetched for the selected release,
bounded to 5 MB PNG/JPEG and embedded with the reviewed tag batch.

## Accounts and online services

No credentials are shipped. Credentials use Electron's OS secure storage. An
unavailable keyring or Linux `basic_text` backend blocks credential saving rather
than writing account secrets in plain text. Settings exports exclude accounts.
See [Electron secure storage](https://www.electronjs.org/docs/latest/api/safe-storage)
for OS protection semantics; Windows storage does not protect against other apps
running as the same signed-in user.

1. **ListenBrainz:** paste your personal token, enable submissions and save.
2. **Last.fm:** enter your application's API key/secret and save; choose **Connect**,
   authorize in the browser, then **Finish connection**. Enable submissions explicitly.
3. **Similar artists:** use the current artist and configured Last.fm API key. Results
   offer matching songs already in your library (up to 200 per artist).
4. Use **Send pending listens**, **Discard pending listens** or **Disconnect** when needed.

**Discord:** enter your Discord application ID and explicitly enable sharing in
Accounts, then play a song with the Discord desktop app open. The local IPC adapter
shares only title/artist as listening activity, deduplicates updates and limits them
to one every 15 seconds. Pause clears the activity on that update budget;
disable/quit clears and closes the connection. There are no room join buttons,
account permissions or artwork uploads. Real Discord application/client visibility
needs acceptance; protocol tests use an isolated local named pipe/socket.
See [Discord RPC](https://docs.discord.com/developers/topics/rpc) for the native IPC
and activity protocol. Profile visibility follows the user's Discord settings.

Qualified listens (songs at least 30 seconds; half listened or four minutes) queue
in SQLite. Payloads contain tags, duration and the original start timestamp, not
local paths. Retry runs every minute in bounded batches with backoff; the outbox
keeps at most 1,000 jobs and expires them after 30 days. Jobs are removed only after
provider acknowledgement. Lost acknowledgements can cause a repeated submission;
this is not an exactly-once guarantee. Offline fixture tests exercise both services
and restarting the outbox; live account acceptance is deliberately pending.

Protocol references: [Last.fm authorization](https://www.last.fm/api/webauth),
[scrobbling](https://www.last.fm/api/show/track.scrobble),
[ListenBrainz API](https://listenbrainz.readthedocs.io/en/latest/users/api/core.html),
[listen format](https://listenbrainz.readthedocs.io/en/latest/users/json.html),
[MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API),
[AcoustID lookup](https://acoustid.org/webservice).

## Radio and podcasts

Radio uses direct public HTTPS audio streams compatible with Chromium. Saved
stations and Radio Browser lookup are implemented; live directory availability is
an acceptance check. Leave a shared room before playing radio. Radio plays locally
through the existing output graph; it is not cached, restored at startup or relayed
as a local file. HLS still needs a decoder.

Follow a public HTTPS RSS/Atom feed to see up to 100 episodes per feed (50 feeds
maximum). **Download & resume** uses the bounded two-day file cache before playback.
Resume positions are stored separately every five seconds; a sudden crash can lose
up to five seconds. **Save download** keeps an episode in the incoming music folder.
Active/next audio is protected from cache pruning. Current feed support handles
ordinary RSS/Atom enclosure feeds and rejects DTD/entities; complex provider feeds
and live network error behavior need acceptance. Progressive download playback,
YouTube/Spotify players and casting still require code.

## Sharing server onboarding

Follow [server/README.md](../server/README.md) for domain/TLS/create secret and optional
Telegram access. Enter the URL once under **Getting started → Check and save server**;
then create/join through Sharing. The checker validates health/storage and requires
HTTPS/WSS for non-loopback servers.

Optional Compose configuration (paths already covered by its state volume):

```dotenv
ROOM_STATE_FILE=/var/lib/rhythm-dock/rooms.json
ROOM_RETENTION_DAYS=7
# Enable only if crash collection is desired:
CRASH_REPORTS_DIR=/var/lib/rhythm-dock/crash-reports
```

Room snapshots preserve identity, queue and settings, restored paused. Server
restarts reconnect existing desktop clients. On the same desktop, the **Resume
hosted room** action reclaims the OS-encrypted host identity after reopening the app;
**Leave** forgets it. The host must still have the audio files. Member/upload grants,
pending contributed files and Telegram chat pairing are temporary. Pair Telegram
again after server restart. Snapshot retention is 1–30 days and recent changes can
lag disk by 500 ms. Real TLS/multi-network listening remains unchecked.

Crash reporting stays off unless the user enables it and supplies an endpoint.
The optional server receiver accepts `/api/crash-reports` with bounded predefined
diagnostic fields, removes sensitive fields and keeps reports for 30 days. No
report viewing/admin portal is implemented. Local diagnostics remain available
without a server.

## Desktop settings

Installed Windows/macOS applications can enable launch at login; Linux autostart
still needs a desktop-entry implementation. Launch accepts multiple audio
paths plus `--play` (replace/play), `--enqueue` (append without starting an empty
queue) and `--hidden`. A running app queues file-manager batches in one window.
Packaged portable builds recognize `rhythm-dock.portable` beside the executable
(or `PORTABLE_EXECUTABLE_DIR`) and use `RhythmDockData` there, without importing normal
profile data. OS-encrypted credentials are tied to their machine, including in
portable mode. Packaged/platform acceptance is pending.

Track notifications are disabled by default; macOS action buttons and Touch Bar
transport code are present but untested on a real Mac. MPRIS/macOS Now Playing,
Wayland acceptance and automatic updating remain open. Preference import uses an
allowlist and confirmation, preserving accounts/device routing/queue; restart to
apply everything. Interface i18n and a full assistive-technology audit are unfinished.

## Reproduce local verification

PowerShell, from the repository root:

```powershell
Set-Location '.\Rhythm Dock'
npm test
npm run test:ui-smoke
```

With a user-provided FFmpeg path, also run:

```powershell
$env:FFMPEG_TEST_BINARY = 'C:\Tools\ffmpeg\bin\ffmpeg.exe'
npm run test:media-integration
npm run test:ui-smoke
```

On Linux/macOS from the app directory, use
`FFMPEG_TEST_BINARY=/absolute/path/to/ffmpeg npm run test:media-integration` and the
same prefix for `test:ui-smoke`. Electron UI/DB tests require a desktop display
(or a configured virtual display); they were accepted locally on Windows only.

`npm test` includes pure logic, a 20,000-song database fixture, provider/outbox mocks,
actual loopback desktop clients, a child-process server restart/reclaim and the
server suite. UI smoke uses isolated app data, 10,000-row library/queue fixtures,
real radio/media and organizer IPC, and crash recovery. FFmpeg tests assert actual
durations, tags and byte-exact preservation. Live credentials, internet listening,
hardware/packaging and whole-app CPU/long-session memory budgets stay unchecked.
